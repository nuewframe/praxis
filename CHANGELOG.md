## [0.6.0] — 2026-08-10

### Added
- **Single-File Growth Initiatives (`INIT.`) & `create-initiative` Skill** — Refactored `skills/create-wave` and added `skills/create-initiative` to initialize single, intent-named initiative files (`docs/product/initiatives/INIT.<initiative-name>.md`) that refine progressively from high-level intent ($Iteration_1$) into detailed specs ($Iteration_N$), eliminating big-bang 4-file folder scaffolding.
- **Living Capability Records (`CAP.`) & `create-capability-record` Skill** — Established `skills/create-capability-record` to scaffold and update `docs/capabilities/CAP.<capability-name>.md` as the single living source of truth per domain for UX, technical architecture, seam contracts (`<name>@vN`), and quality invariants.
- **Upstream Domain Event Storming (`skills/event-storming`)** — Added upstream discovery skill to map raw business requirements and domain events to bounded contexts, candidate `CAP.` records, and initial `INIT.` growth initiatives.
- **Downstream Operational Feedback Intake (`skills/ingest-operational-feedback`)** — Added downstream human-in-the-loop operational feedback intake skill to distill incident post-mortems, operator friction logs, and SLO reviews directly into `CAP.` invariants and remediation initiatives.
- **Unified Product Dashboard & Context (`docs/product.md`)** — Consolidated doctrine, governance, and living roadmap into a single, unified `docs/product.md` hub at the root of `docs/`.
- **Search-Optimized Intent Prefixes** — Adopted standard file naming prefixes across all core artifacts: `CAP.` for living capabilities, `INIT.` for growth initiatives, `ADR.` for architectural decisions, and `SPRINT.` for ephemeral implementation bridges.

### Changed
- **Anti-Over-Refinement Rule Enforced** — Explicitly updated `instructions/lean-delivery-guardrails.instructions.md` and `skills/create-initiative` to forbid up-front $Iteration_N$ over-refinement for early exploratory spikes, keeping $Iteration_1$ lean.
- **Agent Personas Updated** — Refactored [`agents/product-manager.agent.md`](agents/product-manager.agent.md), [`agents/product-designer.agent.md`](agents/product-designer.agent.md), and [`agents/principal-engineer.agent.md`](agents/principal-engineer.agent.md) to operate directly on single-file `INIT.` initiatives, `CAP.` living records, `docs/product.md`, and `docs/product.md`.
- **Always-On Instructions Updated** — Refactored [`instructions/lean-delivery-guardrails.instructions.md`](instructions/lean-delivery-guardrails.instructions.md), [`instructions/capability-driven-guardrails.instructions.md`](instructions/capability-driven-guardrails.instructions.md), and [`instructions/code-contribution-intake.instructions.md`](instructions/code-contribution-intake.instructions.md).
- **Sub-Skills Refactored & Enhanced** — Updated `skills/create-product-design-spec` (with Given/When/Then templates & UX matrices), `skills/create-product-architecture-spec` (with Ports/Adapters & seam contracts), `skills/create-quality-spec` (with test pyramid & 4 Production Readiness anchors), `skills/start-thin-slice`, `skills/close-sprint`, `skills/bootstrap-project`, and `skills/provision-project-overlay`.
- **Validation Probes Updated** — Updated `scripts/validate-plugin.sh`, `scripts/gen-doctrine-index.sh`, `.praxis-canon.json`, `AGENTS.md`, and `GEMINI.md` to reference `docs/product.md` and `CAP.` records.

## [0.5.0] — 2026-07-25

### Note on the version number

This release moves files and restructures the canonical docs — a **major** change under `docs/project-context.md` § Versioning. Praxis is pre-1.0, so the major signal is carried by the minor position: this ships as **0.5.0**, not 1.0.0. That is standard `0.y.z` semver, not an exception to the policy, and the policy has been amended to state it explicitly so the question does not recur. `1.0.0` is reserved for the deliberate declaration that the skill, instruction, and agent interfaces are stable — not for the next breaking change that arrives.

No skill, instruction, or agent was removed, and no adopter's tree breaks. The file moves are relocations with references updated. The one rule change below — `create-wave`'s category mandate — is a **relaxation**: it widens what counts as a valid wave rather than invalidating anything already authored. The real-repo evidence bar noted in 0.4.0 is met for exactly one path in this release — `derive-waves-from-history` was applied end-to-end to an external product before it was generalized, and that application changed the path rather than confirming it. It remains unmet for the method as a whole; one validated path is not a validated method.

### Changed

- **`check-no-skipped-tests.sh` and `check-no-sleep-waits.sh` are declared `n/a` against Praxis, with the reason recorded inline.** Both target a product test suite Praxis does not ship, and their only in-tree matches are the deliberate dirty fixtures under `scripts/__fixtures__/` that `test-probes.sh` already asserts must exit 1 — a stronger proof of those probes than a scoped vacuous pass would be. Adding an exclusion flag was considered and rejected: changing a host-facing probe's scan semantics to accommodate Praxis's own fixture layout would export this repo's problem into every adopter's build.
- **`derive-waves-from-history`** — the late-adoption entry point that sat empty between greenfield `bootstrap-project` and code-level `refactor-layered-to-capability`. It derives a wave structure for a product that already shipped from the record it already has (release history, ADRs, capability records, commit log) without inventing the acceptance criteria and hypotheses that were never written. Delivered waves get a README with evidence-cited slices and **no** hypothesis card or criteria; open waves get the full four documents; a reader can tell a reconstructed record from a maintained one without being told.
- **The path was validated against a real external product before it was written.** The slice's own bar — *generalize only after the pattern has been applied to a project that is not Praxis* — was met by applying it end-to-end to `nuewframe/logickit`, a five-generation product with partial prior adoption and no dashboard. That application **changed** the path rather than confirming it: four of its rules exist because LogicKit hit cases Praxis's own single-tree retrofit could not — a product with several roots, wave documents whose declared status their own repository contradicts, drifting slice-identifier schemes (`TS-NNN` vs `ST-NNN`) whose obvious correspondence was deliberately **not** applied because inference that feels obvious is the shape fabrication takes, and the fact that late adoption usually means *some* Praxis unmaintained rather than none.
- **Context placement beyond one repository, resolved as precedence rather than generation.** See [ADR.260725.17](docs/architecture/adr/ADR.260725.17-context-placement-beyond-one-repo.md). A package tier joins the precedence stack — walk toward the repo root, nearest declaration wins, a package states only what differs. An optional `paths.product_root` marks a repository as one **part** of a product spanning repositories, and such a repository's dashboard must declare that scope instead of presenting a fragment as the whole. Nothing becomes mandatory for a single-repository project. The dual-home generator is **retired as a concept** rather than deferred again: under precedence a fact lives at the level where it is true, so there is no second copy to sync.

- **Concurrency is now mechanically checked, after the deferral's named trigger fired.** `check-sprint-disjointness.sh` and `check-contract-freshness.sh` read a per-sprint **Sprint Footprint** block (`scripts/data/sprint-footprint.schema.json`) and were built only once two slices were actually dispatched concurrently — the trigger their design named. Both are warn-first via `.sprint-coordination.json` and skip cleanly when fewer than two sprints declare a footprint, so the artifact never becomes mandatory before it is used.
- **The four-condition disjointness rule was insufficient, and the real dispatch is what showed it.** The two concurrently-dispatched sprints were disjoint on all four axes — capabilities/file globs, persistent resources, config keys, frozen-contract dependency — and collided anyway. The footprint gained two fields the original design did not anticipate: `closeArtifacts` (both sprints had to write the CHANGELOG, dashboard, wave README and capability record; the four conditions model implementation footprint, not close footprint) and `baseRevision` (both worktrees were cut two releases behind the frozen tip, and every contract hash still matched because there were no contracts). Close-artifact overlap is reported as **advisory** — it does not forbid concurrency, it requires close to be reconciled centrally rather than raced.
- **A dispatch's own artifacts belong to no footprint.** Git worktrees created inside the repo hold a full second copy of the tree, and sprint-shaped test fixtures look like sprints to a probe walking from the root. Both broke repo-wide scans during the dispatch and are now excluded from every scanning check.
- **`scripts/test-sprint-coordination.sh`** — self-test for both probes, with fixtures taken from the sprints that actually ran concurrently rather than invented ones.

- **The one verbatim-duplicated doctrine fact is now generated.** Each always-on guardrail's `applyTo` glob was declared in its instruction file's frontmatter *and* restated as prose in `using-praxis`, hand-synced with nothing detecting divergence. `scripts/gen-doctrine-index.sh` now renders it from the frontmatter — the instruction file stays the single source — and `--check` runs in CI, so a hand-edit inside the generated block fails the build. This cashes in the pilot [ADR.260720.02](docs/architecture/adr/ADR.260720.02-generated-tier-table.md) framed as "one fact, proven before any decision to generalize".
- **The line that generalizing drew: a fact stated twice is not the same as text appearing on two surfaces.** README's guardrail Scope column, the persona table's "when to be this persona" column, and the rule bullets are three summaries written for three different readers. They were never required to agree word-for-word, and generating them would have replaced curated prose with frontmatter descriptions — a readability loss for a rigour that was not missing. They are deliberately left alone. The dual-home generator deferred to its own wave was not needed and was not invented.
- **Inventory parity now runs in both directions.** It proved *on disk → mentioned* but never *mentioned → on disk*, so deleting a skill, guardrail, or persona would have left stale claims across all three canonical surfaces with a green build. A name claimed by `README.md`, `docs/project-context.md`, or `using-praxis` must now exist on disk, with fence and `praxis:allow-path` exemption for illustrative cases. Verified by deliberate defect, then reverted.

- **A repository path named in prose is now checked, not just one written as a link.** The cross-reference check matched four code-directory prefixes in backticks, never `docs/`, and reported no line number — so deleting a directory stranded every prose reference to it silently, findable only by grep. Check #4 is now line-scoped and covers backticked *and* bare file paths under `docs/`, `skills/`, `agents/`, `instructions/`, and `scripts/`, reusing `citation_scan.py` for fence, blockquote, and `praxis:allow-path` exemption. Negative-tested six ways: broken backticked path, broken bare path, fenced path, `<placeholder>` segment, marker with a reason, and marker without one.
- **Three deliberate narrowings keep the check from becoming noise.** It matches *file* paths, not bare directory names — directories are where illustrative host-repo structure concentrates, and including them turned 7 real findings into 19 mostly-spurious ones. It excludes markdown link constructs, because a prose path resolves from the repo root while a link target resolves from the linking file's directory; conflating them reported a correct link as broken. And it applies **no** code-span exemption, unlike the version scanner — for a path, backticks are the ordinary notation, so exempting them would excuse nearly every reference the check exists to validate.
- **`praxis:allow-path` joins the marker vocabulary (now seven).** Fourteen historical citations — released `CHANGELOG` entries and ADRs naming files that existed when written, including an ephemeral sprint file deleted by design — now declare themselves at the line where they appear. Rewriting those entries so they resolve would falsify history.
- **Seven script headers citing a plan file deleted with `docs/plans/` are fixed.** Genuine dangling references, and after this markdown carries none. The class survives only in `.sh` header comments, which this check does not reach — a deliberate, recorded coverage boundary rather than a silent gap.

- **Declared exceptions move inline: citation is no longer treated as assertion.** Implements [ADR.260725](docs/architecture/adr/ADR.260725-inline-declared-exceptions.md). The version single-source audit and the terminology check could not tell a document that *asserts* a literal from one that *cites* it, and the answer was path allowlists — 8 entries in `.version-bump.json`, 3 in `.praxis-canon.json`, most of them directory-wide. **Both lists are now deleted in full.** In their place: a literal inside a fenced block, blockquote, or inline code span is a citation by position (no configuration), and a citation in running prose carries `<!-- praxis:allow-version-literal reason="…" -->` or `<!-- praxis:allow-term reason="…" -->` on the line above. **The reason is mandatory — a marker without one fails the build**, because an unexplained exemption is the defect being removed rather than a smaller version of it. Both markers are registered with `check-escape-hatch-usage.sh` and counted in the Trust Receipt, so exemption growth is a decision a reviewer keeps making instead of silent debt.
- **`scripts/citation_scan.py`** — the single implementation both literal scanners consume, with `scripts/test-citation-scan.sh` as its self-test. It exists as one module rather than two copies because ADR.260725's risk table names the exact regression to avoid: a second fence parser repeating the marker-length false negative that check #14 already hit. Check #14's fence rule moved here rather than being duplicated.
- **The migration restored coverage that had been silently disabled.** A stale claim about the *current* plugin version anywhere under `docs/architecture/adr/` previously passed — the whole directory was exempt — and now fails; verified by planting one, confirming the old rules passed it and the new rules catch it, then reverting. Migration was gated behind a `--report-only` parity pass (`bump-version.sh --audit --report-only`) before either list was deleted, per the ADR's sequencing. `--check` and `--write` were left untouched and their output verified byte-identical, since those paths are release-critical.
- **Two findings from the migration worth recording.** First, **Layer 1 absorbed nearly all of it**: the citations that surfaced were version tokens that read better as code literals anyway, so the marker *range* form ADR.260725 deliberately left undecided was never needed — the one shape that would have forced it, a literal inside a markdown table row where a comment line breaks the table, is solved by backticks instead. Second, two of the three retired terminology entries (`CHANGELOG.md`, `.praxis-canon.json`) were **dead weight** — both sit outside the scanned directories, so they exempted files the check never read.
- **Terminology drift (check #10) is now line-scoped.** It scanned whole files and reported the file, which left no line for a marker to attach to; making it report `file:line` was a precondition for inline declaration, not a cosmetic improvement.
- **The product dashboard has one name: `docs/product/README.md`.** Two names were in circulation — Praxis's own tree used `docs/product/README.md` while `create-wave`, `close-sprint`, `provision-project-overlay`, and the product-manager persona illustrated it as `docs/product/PRODUCT.md`. Neither was wrong, which is precisely the defect: an adopter following Praxis's tree as a template had to guess which convention was current. All seven live references now name `docs/product/README.md`, matching the `<tree>/README.md` convention already established by `docs/architecture/README.md`. **No adopter must migrate.** Applying the evolution policy's breakage test — does any tree that validated before the change fail after it? — the answer is no: every reference hedged with *commonly* or *e.g.*, so the path was always advisory, and no script, probe, or template parses it. A project that prefers `PRODUCT.md` keeps it by setting `paths.product_dashboard`; only the default changed. Released `CHANGELOG` entries naming the old path are left intact — they cite what was true when written. <!-- praxis:allow-path reason="released entry citing the dashboard filename as it stood at that release; the name converged later and rewriting a shipped entry would falsify history" -->
- **Five probes whose clean verdict is vacuous now say so.** The four production-readiness anchors and `check-port-adapter-parity.sh` scan globs Praxis has no files under. They are still executed — that proves the scripts *run*, on both the bash 3.2 floor and bash 5, which `bash -n` does not — but each carries a `note` recording that the pass proves execution and not that the anchor holds on real runtime code. The gate is not permitted to read as a stronger claim than it is.

- **`create-wave` no longer mandates a wave category.** Step 1's `wave-feature-*` / `wave-platform-*` / `wave-ext-*` table is gone, the folder pattern is now `wave-<name>/`, and the README title template is `# WAVE: [Wave Name]`. A wave is the unit of intent; sorting it into a product-org bucket never changed what got built or how faithfully it shipped, so the mandate failed scope-litmus question 4. Grouping conventions are now a host-project decision, recorded in the project's own `docs/project-context.md`. **This is a constraint relaxation, not a rule removal** — every existing wave folder stays valid, category prefix and all, and no skill, script, probe, or template ever parsed the category segment (verified by sweep: all seven references were confined to `skills/create-wave/SKILL.md`). The evolution policy's deprecate-one-minor-version-before-removal clause exists to protect adopters from breakage; there is no breakage here, so it does not apply.
- **`project-context.md` is now the method document, not just governance.** It absorbed the doctrine layer — why the method exists (trust transfer), the ten opinions it is opinionated about, the PLAN → TRIAGE → BUILD → LEARN → TEACH spine, where fidelity is made, and the honest enforcement split — ahead of the existing scope rule, architecture, evolution policy, and quality gates. Sections 1–9 are the method (read to *use* Praxis); sections 10–11 are the plugin (read to *change* it).
- **All project context moved under `docs/`**, so Praxis follows the convention it prescribes to host repos in `bootstrap-project` Step 6: `project-context.md` → `docs/project-context.md`, `DEPLOY.md` → `docs/DEPLOY.md`, `CLAUDE.md` → `.claude/CLAUDE.md`. The repository root now holds only `README.md`, `AGENTS.md`, `GEMINI.md`, and `CHANGELOG.md` — each held there by an external contract (GitHub front page, the root-only AGENTS.md convention, `gemini-extension.json`'s `contextFileName`, Keep-a-Changelog), documented in `docs/project-context.md` § *Why the root is nearly empty*.
- **`using-praxis` slimmed from ~14.7 KB to ~12 KB.** It is re-injected on every session start, `/clear`, and compaction in five harnesses, so its size is paid repeatedly. Doctrine moved to `docs/project-context.md`; the tooling table moved to `README.md`; the skill index was regrouped by pipeline stage. The three always-on guardrail summaries were deliberately kept — on harnesses without `applyTo`, they are the only always-on surface.
- **`bump-version.sh --audit` now fails closed and detects stale versions.** It previously grepped for the *current* version, which by construction could never find a document still claiming an older one. It now scans the `audit.scan` paths for any semver literal and exits non-zero on anything not either mechanically synced (`.version-bump.json` `files`) or declared in the new `audit.allow` list with a stated reason.

### Added

- **Praxis now runs the gates it ships, and declares the ones it does not.** CI executed exactly one of the twelve `check-*.sh` probes; the other eleven were only `bash -n`-parsed, so "we ship this check" and "this check passes" were two different claims about the same script. A new `.self-conformance.json` declares, per probe, whether Praxis runs it against itself — and when it does not, a mandatory `reason`. `.github/run-self-conformance.sh` executes every `runs: true` gate and prints an explicit `n/a — <reason>` line for the rest, so the full twelve-gate verdict is visible in the build. The loop deliberately does not short-circuit on first failure: it reports every gate, then exits non-zero, because a half-reported build hides gates behind the first red one. Current split: **10 run, 2 reasoned `n/a`**.
- **Self-conformance declaration parity in `validate-plugin.sh`** (check #16) — every shipped `check-*.sh` must be declared exactly once, entries must name a script that exists, and a `runs: false` entry must carry a non-empty reason. A new probe can no longer ship and simply never run against this repo with nothing recording whether that was a decision or an oversight. Negative-tested five ways: undeclared probe, stale entry, empty reason, duplicate entry, and a missing manifest.

- **`ADR.260725` — declared exceptions move inline. Decision accepted; implementation deliberately not in this release.** The version single-source and terminology gates cannot distinguish a document that *asserts* a literal from one that *cites* it, and the current answer — path allowlists — inverts default-deny: exempting `docs/architecture/adr/` means a future ADR with a genuinely stale current-version claim passes silently. The accepted design is three layers: structural citation detection reusing check #14's fence rule, inline `praxis:allow-*` markers carrying a mandatory reason, and exemption growth surfaced through `check-escape-hatch-usage.sh` and the Trust Receipt. **The path allowlists still exist in this release** — migration is gated behind a `--report-only` parity pass because `bump-version.sh --audit` is release-critical, and is tracked as `TS-008` of wave-self-conformance. Two allowlist entries were added an hour apart while producing this release, which is the evidence that made it a pattern rather than an incident.
- **`docs/plans/` removed; `docs/product/waves/` is the single home for planning intent.** The directory held one pre-adoption engineering plan. Its delivered content is now cited as evidence by the derived waves, and its one still-open commitment — the machine-readable sprint footprint plus the disjointness and contract-freshness probes, deferred to a named trigger — was migrated into `TS-005` of the executable-seams wave, whose `product-architecture.md` is now that design's only home. A migration, not a discard: nothing open was dropped, and no shipped plan was rewritten into wave shape. `.version-bump.json`, `.praxis-canon.json`, `validate-plugin.sh`, and `docs/project-context.md`'s tree shed their now-dead references to it. Removing it also emptied the frozen-tree carve-out in `ADR.260725`, which is dropped rather than kept as a rule with no instance.
- **Praxis's own wave structure, derived from its delivered history.** Seven waves now live under `docs/product/waves/` and are indexed on the product dashboard: the method spine, multi-harness reach, executable seams, production-readiness posture, and trust transfer as **delivered**; self-conformance and brownfield adoption as **open**. The delivered waves are *derived records* — README only, with each slice citing a release entry, ADR, or capability record, and carrying no hypothesis card, acceptance criteria, or educated-theory documents, because none were written at the time. `ADR.260725.10` records why that distinction is the whole basis of the retrofit: deriving an intent map from records that already exist invents nothing, while rewriting a shipped plan into a wave complete with criteria it never had would assert validated learning that never happened. Waves are derived from coherent value themes, deliberately **not** one per capability — `skills`/`enforcement`/`distribution` are ownership boundaries, and mapping them one-to-one would produce the implementation-bucket anti-pattern `create-wave` prohibits. This also closes a real gap: `bootstrap-project` is greenfield and `refactor-layered-to-capability` migrates legacy code rather than legacy intent, so until now the most common adoption path had no answer beyond "keep an archive and start fresh."
- **Evolution policy gained a *relaxing a rule* case** (`docs/project-context.md` § Evolution policy). The policy previously spoke only to *removing* and *breaking* a rule, and was silent on widening what counts as valid — so a change that breaks no adopter had no classification and defaulted to the full deprecation cycle. The new case is governed by an objective breakage test ("does any tree that validated before the change fail after it?"), requires the CHANGELOG entry to assert that prior usage stays valid, and takes the stricter classification when a change relaxes one constraint while tightening another. Decided in `ADR.260724`, which the `create-wave` change below is the worked example for.
- **`docs/product/README.md`** — the product overview and wave dashboard anchor Praxis tells host repos to keep, completing the `<tree>/README.md` convention already used by `docs/architecture/`. It now registers Praxis's first wave, `wave-self-conformance`, and declares `docs/plans/` as the pre-adoption archive rather than retrofitting a shipped engineering plan into wave format. It states two caveats plainly: the wave's first four slices were defined in a sprint before the wave existed (a recorded precondition deviation, not a pattern to copy), and self-conformance is not the real-repo validation the evolution policy demands.
- **Version single-source check in `validate-plugin.sh`** (check #13) — delegates to `bump-version.sh --audit`, making an undeclared or stale version literal a build failure. Caught two live drifts on introduction: `docs/project-context.md` claiming `v0.4.0` in prose and `docs/architecture/README.md` claiming `0.3.0`, two releases behind. It then caught a third unprompted: `ADR.260724` citing the release context of its own decision, which surfaced that the gate had no concept of an immutable historical record. Resolved by declaring `docs/architecture/adr` in `audit.allow` — the same class as the existing `docs/plans` allowance — rather than editing the ADR's reasoning to satisfy a linter.
- **Link-resolution check in `validate-plugin.sh`** (check #14) — every relative markdown link must resolve. Inventory parity (check #7) only proves a name is *mentioned*, never that a link *works*, which is how a docs reorganization strands references silently. Three exclusions, each load-bearing: fenced blocks (template content whose paths resolve from the destination document), `<placeholder>` segments, and external schemes. Found one live defect on introduction — the planning-stage banner quoted as an unfenced blockquote in `create-quality-spec`, now fenced to match how `create-wave` and `bootstrap-project` present the same text. Negative-tested three ways: a broken link is reported with `file:line`, and both a fenced link and a `<placeholder>` path are correctly ignored.
- **CHANGELOG structure check in `validate-plugin.sh`** (check #15) — version headings must parse, be unique, descend newest-first, lead with `[Unreleased]` when present, and include an entry for the version `package.json` declares. This is the gate for the defect that motivated it: a lost `## [0.4.0]` heading silently re-parented an entire release's entries under the heading above it and went undetected. Negative-tested four ways — removed heading, duplicate heading, non-descending order, and a hyphen where the format requires an em dash.

### Fixed

- **`docs/` was never included in the npm package.** `package.json` `files[]` omitted it while `using-praxis` linked to `docs/coverage-matrix.md`, so every npm and OpenCode install shipped with that link dangling. `docs` is now published.
- **Removed the version literal from prose entirely.** `package.json` is the sole authored version; `docs/project-context.md` § Identity and `docs/architecture/README.md` now point at the tooling instead of restating a number that goes stale.

## [0.4.0] — 2026-07-20

### Note on evidence

This release ships the course-correction toward the plugin's own sharpened Problem statement (trust transfer / execution fidelity). The plugin's own evolution policy (see `project-context.md` § Evolution policy) says a minor bump's CHANGELOG entry "must cite the real-repo evidence... a bump that can only cite dogfooding does not qualify." That evidence does not yet exist — real-repo validation (running a full wave → sprint → close-sprint cycle at `profile: full` against an actual project) is the immediate next step after this release, not a precondition already met. Stated here plainly rather than silently omitted: everything below is verified by self-test and independent reconciliation against each item's stated Done criterion, not by real-world use yet.

### Added

- **`## Problem` section in `project-context.md`** — states the plugin's actual problem plainly: trust transfer. An agent-generated delivery artifact looks the same whether the agent reasoned hard or pattern-matched a template; Praxis's job is closing that gap, and its primary output is **execution fidelity** — the agent demonstrably did the disciplined work, and where it didn't is visible.
- **`## The method at a glance` section in `project-context.md`** — the ordered PLAN → TRIAGE → BUILD → LEARN → TEACH spine, Trivial/Standard/Major tier branching, and a stage-by-stage "where fidelity is made" table, so the high-level flow is legible from the constitution alone instead of only from the file tree.
- **4th scope-litmus question** — "Does it measurably improve the agent's execution fidelity, or close a known agent failure mode?" A rule can be universal, disciplined, and defensible and still not belong in the plugin if it fails this question; universality is necessary but not sufficient.
- **Strengthened evolution policy** — real-repo validation is now the non-negotiable step before a minor bump; dogfooding the plugin on itself no longer substitutes, and a bump's CHANGELOG entry must cite real-repo evidence (see the Note above — this release itself does not yet meet that bar, by design, and says so).
- **`README.md` § "Enforcement, honestly"** — discloses the script-enforced / human-signed / agent-attested gate split in the opening pitch, guarded by a new `.praxis-canon.json` `requiredPhrases` lint (the inverse of `forbiddenTerms`) so the disclosure can't silently regress. `scripts/validate-plugin.sh` gained a 12th check enforcing it.
- **`scripts/check-design-approval-gate.sh`** — the plugin's first gate that is genuinely hard-fail with no warn mode and no opt-out. For every Major-tier sprint, verifies the referenced ADR's status is `Accepted` and the sprint's Design Approval block is genuinely signed, not template placeholders. Drift detection was independently proven twice before this release.
- **`verify-and-assemble-pr` Step 6 "Artifact-fidelity review"** — a separate-head rubric grading whether an ADR's alternatives, a Design Approval signature, an ambiguity log, a hypothesis card, or a risk-register entry carries real substance or is boilerplate. - **`verify-and-assemble-pr` Step 7 "Trust Receipt"** (renumbered from Step 6) — aggregates gate-kind status (script-enforced / human-signed / agent-attested), escape-hatch usage, and Step 6's verdicts into one human-readable block per PR — the first concrete artifact answering the plugin's own trust-transfer problem statement directly.
- **`scripts/check-escape-hatch-usage.sh`** — diff-scoped scanner for the four `praxis:allow-*` escape-hatch markers, reporting exact file:line. Informational only, always exits 0 — the point is that using an opt-out is never silent to a reviewer, not blocking it.
- **`docs/architecture/`** — the plugin's own capability record, created for the first time, per its own `close-sprint` doctrine that "the capability record is the truth." A system overview, three capability records (`skills/`, `enforcement/`, `distribution/` — `agents/` and `instructions/` folded into the overview as too small/stable to warrant their own record), and three ADRs for the durable decisions in this release: the Design Approval gate, the generated tier table, and the fidelity-review/trust-receipt mechanism.

- `lean-delivery-guardrails.instructions.md` — wave/sprint discipline, immutable sprint scope, bidirectional learning at close.
